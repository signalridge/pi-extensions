Continue remembered ordinary agents after eviction or reload using their original ID and handle. Branch-owned bounded receipts validate native child ownership, exact saved history, current definitions and existing isolation before reopening; managed workflow children remain under their owner's recovery controls. Public Agent, registry and legacy RPC calls reject internal session-file and handle-reclaim capabilities. New receipts fence the public physical catalog provider/API/model/baseUrl before cold continuation; only exact routes from Pi AI's public SDK built-in catalog qualify, conservatively including the actual model ID. Unknown/custom endpoints (which may hide credentials in URL paths) are never retained in receipts or native ownership markers, including when parsing saved receipts. Fresh custom-provider agents still run normally without cold-reopen proof. Missing or changed route proof and opaque replay without issuer/profile proof are refused with sanitized fresh-agent guidance. This catalog fence does not qualify authentication-time endpoint pinning or cross-profile/cross-issuer replay. Cold sessions are handed off only after final admission, and failed setup/handoff sessions cannot become live-resume fallbacks. Reject explicit cold `isolated`/`isolation` parameters before allocation instead of dropping them; use a fresh Agent for per-call isolation transitions. Finalize shutdown-written native leaves only with renewed ownership, original-route and plain-history proof on the owning parent branch, and hold leases through actual foreground-resume and teardown settlement.

Manual agent creation now saves model/thinking choices as references to the existing tier catalogue, with explicit approval before adding a new tier and no silent edits to existing tiers. Explicit thinking `off` is reported as unsupported by the current shared tier schema instead of being saved as an ignored pin or translated to inherit. Generated definitions also reference tiers rather than retired model/thinking frontmatter.
