Stop background completions from re-running a parent whose context overflowed the model window. While the latest meaningful response on the branch is a context overflow with no compaction after it, completion notices are added to the conversation without starting a turn, parent-question wakes wait, and one warning per overflow episode asks to run `/compact` (or `/codex-compact` when installed) or start a new session. A compaction or a later successful response restores normal waking; held questions wake after the compaction controller releases, even when a downstream async compaction handler delays release. Idle-gated recovery is session-owned, cancellable, and bounded to 30 seconds without model polling. Transient errors and aborts do not prove recovery. A question cancelled during preparation never discards real queued steering or follow-up input. Previously every completion started another request that resent the same over-window context and failed again. `get_subagent_result` now tells the model that a running or queued agent will notify it on completion, not to poll, and to use `wait: true` only when blocked on the result. Pending clarification questions are injected through `context_with_system`, so Pi's mid-conversation system messages stay in place and the cached prompt prefix survives while questions are pending (as in nicobailon/pi-subagents `f45abdb9`).
