Add opt-in `implementationModel` (`provider/model-id`, resolved through Pi's model registry) and `implementationThinkingLevel` settings. Implementing a plan in the current session switches to that model and thinking level before the implementation request is sent; `/plan exit`, clearing the active implementation, or starting a new plan restores the planning model and thinking level, but only while the session still shows what the handoff applied, so a manual model choice is kept and a manual thinking choice relinquishes the handoff's thinking ownership. The handoff is recorded in the session and survives resume. Apply and restore retain selection ownership through async model selection and final handoff publication, in addition to lifecycle checks. Intervening manual model selections retire the pending switch, even when the user chooses away and back. Thinking provenance is conservative: any unowned thinking change before the expected model is observed is ambiguous, including genuine automatic model-default transitions, because the public thinking event has no source. Apply or restore warns and preserves the current thinking instead of forcing the configured implementation or prior planning level. A safe model-only handoff can proceed, but ambiguous thinking is never recorded as extension-owned or later restored from that handoff. Public branch entries detect changes even when earlier thinking-event handlers delay observation; explicit owned thinking setters are excluded. Manual thinking changes after expected model observation invalidate the operation, including away-and-back choices. Obsolete switches do not mutate, persist a handoff, or compensate into another branch or selection. A thinking-only handoff also retires when a different model is manually selected, even if its effective thinking level stays unchanged. An unknown model, missing credentials, or a refused switch leaves the plan ready on the planning model with a warning instead of implementing on another model.
