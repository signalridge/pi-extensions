# Pi 0.99.1 compatibility

Snapshot: 2026-09-30. The published `@earendil-works/pi-*` packages have `0.99.1` on npm's `latest` tag. The fork released [0.99.0](https://github.com/earendil-works/pi/releases/tag/v0.99.0) and [0.99.1](https://github.com/earendil-works/pi/releases/tag/v0.99.1) directly after [0.87.1](https://github.com/earendil-works/pi/releases/tag/v0.87.1); there are no published 0.88–0.98 release tags to imply support for. The [0.87.1 review](pi-0.87-compatibility.md) remains a historical baseline, not the latest-host claim.

## Host boundary

The development pins for `pi-agent-core`, `pi-ai`, `pi-coding-agent`, and `pi-tui` are 0.99.1. Published Pi peer ranges retain the tested 0.84–0.87 minors and add `^0.99.1`, not an untested broad zero-major range. `pi-subagents-protocol` has no Pi peer or wire-format change. Pi 0.99.1 requires Node >=22.19; CI and release checks use Node 24 and Bun 1.3.14.

The 0.99 host retains the public `TranscriptContext` normalization and `SessionManager` projection/context-edit APIs used by BTW, Codex compaction, recap, and the subagent package's bounded parent-history formatter (which is not dispatched under the current fail-closed inheritance policy). New optional host capabilities include virtual models, provider-stream observation, codemode/nested tool calls, built-in MCP/tool search, and richer tool-result metadata. They do not justify silently replacing independent extension policies or the subagent/workflow boundary.

Virtual models (`api: "pi-virtual"`) must route through Pi's public `ModelRegistry.streamSimple` or a child session's `ModelRuntime`; direct provider streaming deliberately rejects an unrouted virtual selection. BTW uses the registry route for virtual selections while physical calls keep their already-resolved credentials and endpoint. Subagent child sessions pass the parent's runtime; their hidden mention clone and child streaming were exercised with a faux virtual route. The hidden mention turn now receives only the current mention text and a static prompt, not the parent's raw transcript or system prompt.

Pi's persisted projection honors `context_edit` but does **not** include request-local `context`/`context_with_system` privacy hooks. BTW therefore sends the explicit side question without parent history by default; sharing raw projected parent history requires a one-question opt-in bound to a matching physical provider/model (and cannot silently follow a virtual route or changed endpoint). Once such a turn occurs, its side thread is bound to that physical destination: a model or endpoint switch requires a fresh thread so earlier answers cannot relay parent-derived details to a new recipient. Recap makes no automatic provider request by default. Both manual and automatic history-bearing recaps require `--recap-allow-raw-history` plus an explicit physical `--recap-model "provider/model-id"`, with no fallback destination; an auth-resolved endpoint differing from that model's registered base URL also fails closed. This retains the reasoning-off guarantee and makes unfiltered-history disclosure an explicit choice.

Pi 0.99's nested `ctx.executeTool()` calls bypass the agent-level `beforeToolCall` wrapper used by older subagent policy code. Child `ext:` scope and `ask_tools` approval now run through Pi's public `tool_call` hook for both model and nested calls. Activation retains Pi's `deferred` and `defaultActive:false` semantics; selected extension handlers share a bounded deadline without charging human confirmation time. A timed-out hook may still cause side effects after its caller is blocked—this is not a sandbox. The child resource loader includes Pi's public codemode, tool-search, and MCP factories when its extension selectors permit them, without statically importing names absent from older hosts. `pi-stamp` does not let nested-only observations consume the bounded slots reserved for visible top-level result timestamps.

## Verification

`bun install --frozen-lockfile` and the complete `bun run check` passed on the final host-boundary changes with Bun 1.3.14, Node 24, and Pi 0.99.1. The gate includes all 29 package lint/typechecks/tests (260 test files), release/configuration and capability/changeset/version/boundary checks, packed-loader smoke, pack validation, and secret scanning. Four opt-in subagent tests requiring a live provider were skipped.

After the 0.99-specific source changes, isolated packaged-loader smoke activated all 27 extensions independently, the subagent/workflow pair with faux-provider integration/recovery, and all 24 stable extensions together under **each** of Pi 0.84.1, 0.85.1, 0.86.1, 0.87.1, and 0.99.1. The matrix checks loading and SDK activation, not every feature on every older host. A separate real child-session smoke on Pi 0.84.1 and 0.87.1 exercised the legacy `<builtin:read>` source marker and confirmed a selected built-in `read` tool executes rather than being rejected by the new scope gate. Real Pi 0.99 faux-provider tests cover virtual BTW routing, subagent virtual child streaming, nested tool-policy denial/consent and same-name tool ownership, built-in child selector behavior, and visible top-level stamp retention after many nested calls. Parent redaction-hook regressions verify that the mention clone sends only mention text, BTW sends no parent history by default, and Recap dispatches raw history only to an explicitly named physical model after opt-in. Live external providers and MCP servers were not exercised.

## Known boundaries

Cancellable `/new` and `/resume` pre-hooks no longer stop child work: confirmed `session_shutdown` settles the outgoing session while its old branch is still writable. For tree navigation, the extensions veto when agents or workflows have active/unsettled work rather than aborting that work on a mere attempt; a committed `session_tree` seals old subagent records before workflow cancellation can append terminal facts and restores the new branch, preventing old managed stops from landing on the new leaf. Pi still offers no post-veto, pre-leaf commit hook. Another extension can start work during asynchronous summary generation *after* the preflight; such late work is quarantined at commit, not guaranteed to finish. This residual race is not an atomic host fix.

`pi-subagents` still uses a checked compatibility bridge to read private `ModelRegistry.runtime` for full child sessions. If the runtime is unavailable or incompatible, admission now fails before allocating an agent ID or managed tombstone; Pi's public stream helper is not a lossless child-session constructor replacement. Restricted child extension sets now pre-resolve and filter enabled paths using Pi's public package manager *before* loading factories, so an excluded `/mcp` extension cannot preempt a selected built-in. Public resolution can still perform configured package installs just as the normal loader does; it adds a resolution pass and fails clearly on an unreproducible selection. `inherit_context: true` now fails closed instead of silently forwarding pre-hook parent history to a child provider; callers can supply a deliberately reviewed, sanitized summary in the Agent task. Reopening an older child session that already contains inherited raw history is blocked rather than transmitting it after a model or endpoint change. Pi still exposes no post-hook parent transcript or atomic child-request destination pin.

A canceled `/usage` scan now leaves the cache unchanged and returns without rewriting the full cache; ordinary cache lock waits and reads honor cancellation. The optional cache does not steal a lock solely because its mtime is old: a live writer may exceed the former 30-second threshold, and stealing could lose concurrent updates. Orphan locks require explicit cleanup after checking the owner. A synchronous JSON parse or rename already in progress cannot be preempted; cancellation checks surround them. Real credentials, physical terminal behavior, external LSP/MCP servers, and live GitHub data remain outside the faux-provider and packaged-loader tests.
