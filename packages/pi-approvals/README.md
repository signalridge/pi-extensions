# @signalridge/pi-approvals

**Opt-in experimental extension**, tested with Pi **1.0.4**. Loading it explicitly installs a session-scoped human approval broker. Root canonical native `edit`, `write`, `bash`, and public `user_bash` execution additionally require the human's explicit `--approvals-native-tools` certification. It does not enable itself or write global configuration. The independent `@signalridge/pi-approval-core` library owns the version-1 contract and reviewed factories.

## Human workflow

Proposed operations wait with an owned footer count. They do **not** open unsolicited dialogs, replace the editor, steal native/foreign dialog focus, or automatically ask a parent model for clarification.

- `/approvals` or `/approvals list` lists pending IDs, source labels, and operation kinds.
- `/approvals review <id>` or `/approvals approve <id>` opens a full bounded review and a human decision. Typing `approve <id>` without the command/confirmation does not authorize anything.
- `/approvals deny <id>` closes exactly that request, including while a review/foreign dialog is open; denial opens no UI and never grants another request.

Commands run while tools wait; no `waitForIdle` is used. In TUI mode a full-terminal public overlay shows the escaped full diff or exact command/CWD/source. Header/controls/body fit terminal bounds; narrow terminals use a fully scrollable document fallback, including at one column. **Ctrl+A** approves that one review; **Esc** denies; Up/Down/PgUp/PgDn/Home/End navigate the review. Enter does not approve. There is no automatic next review, so repeated approval keys cannot approve subsequent requests. A currently observed public native/extension dialog must close before a review opens. A synchronous, short-lived non-capturing public overlay bridge borrows the TUI, completing only after its native admission; the review then owns a raw overlay and closes only its identity handle, never the native pop-last callback. Later capturing and nonCapturing overlays therefore survive cancellation, denial, expiry and retirement: the cancelled review closes and releases its review lock without waiting for a foreign dialog to close. The foreign dialog retains focus and remains respondable. An unfocused review renders no rows, so native confirm/select/input questions are not obscured; focus transitions request a redraw and native focus restoration may safely resume the same review. Affirmative completion still requires the review's own focus. Normal editor draft/focus restoration belongs to the public custom-UI host contract; this extension never writes editor text.

Reviews use lossless hard wrapping, never word wrapping that discards a separator. Over-wide or zero-column grapheme clusters and Thai/Lao AM characters rewritten by native output normalization are escaped by code point. The compact fallback additionally exposes preview whitespace as `\u{hex}` (including newlines) and doubles literal preview backslashes, so spaces, data newlines, soft wrapping and literal escape text remain distinguishable. The scrollable header labels this preview representation; operation bytes and hashes are unchanged. Layout is cached across scrolling, and invalidated on width or compact-mode changes. Regression coverage includes actual native terminal writes after normalization, not only pre-normalization composed snapshots.

RPC uses the public native `confirm` transport when the human invokes the command. The client must display the full review and reply to the fresh `extension_ui_request.id` using `extension_ui_response`; lifecycle approval IDs and model text are not transport nonces. RPC clients must preserve human-only response ownership. A dialog timeout denies. Print/JSON/no-UI modes deny immediately, before native filesystem/process mutations.

Each approval is per-operation. There is no allow-all mode or permission cache, no response tool, and no background conversion of built-in bash. Pending operations are immutable; the broker caps pending requests at 32, retains at most 128 metadata-only resolutions, and expires requests after five minutes. Caller cancellation, committed branch/session divergence, reload/invalidation, missing UI, callback errors, and peer retirement fail closed. Native rename/custom-entry appends and parallel results preserve append affinity using full branch-entry fingerprints. Vetoed navigation and aborted summaries do not retire an unchanged session. Committed `session_start` and `session_tree` bindings install fresh brokers and wrapper closures; captured old services remain permanently retired. Neither cancellation nor denial resolves another request.

## Coverage and ownership

A loaded extension always advertises one typed service, including before startup and after unavailable/collision/retirement failures; discovery reports no peer only when the extension is absent. Discovery checks broker liveness, including canonical binding, session/branch and UI availability, even when no request is pending. On retirement or liveness loss it advertises a distinct, present rejecting service, so previously captured post-approval launch guards fail permanently instead of authorizing work after asynchronous startup. An unavailable service never invites ungated fallback or reconnects an old capture. `/approvals` reports the root policy to the human.

**Root certification is required:** `--approvals-native-tools` is a public boolean CLI flag, default **false**. The human certifies that canonical backends are the host's standard local native Pi backends. Without it, root canonical calls and user bash deny clearly, before process/filesystem mutation, and original backends are **not replaced**. The human service can still review independently integrated child/background operations that construct their own known native factories. The model cannot enable this policy through a tool.

With certification, committed session bindings install reviewed definitions only for available admitted canonical tools. Missing/excluded tools are stronger host admission, never activated by this extension. Known selected extension/custom canonical collisions are rejected, not replaced. The exact current stricter active loadout is restored after late registration, including SDK initial allowlists and earlier Plan deactivations. Each canonical call must have a captured reviewed binding of that exact name with matching effective schema/description/source metadata; an empty or partial initial binding never admits a later canonical registration. Such arrivals are blocked, not silently rebound or added to this extension's loadout. Subsequent ownership loss of captured bindings blocks calls and retires requests. Each invocation also rechecks the exact tool's live active admission through post-approval IO, so a later Plan restriction withdraws pending ordinary writes without another approval or restoring excluded tools.

**Public-SDK limitation:** Pi 1.0.4 labels `AgentSession.baseToolsOverride` backends `builtin:<name>`, even when their operations are custom, rejecting, or remote. Public metadata cannot certify backend provenance. The flag is explicit human certification, **not metadata proof**. SDK hosts with overridden backends must omit it and supply an explicit known-backend reviewed integration. Never use this flag to silently substitute unknown custom operations with local operations.

Reviewed bash uses the core's **owned POSIX backend**, not SDK local-backend delegation. The native SDK still owns tool output/truncation. Ownership is rechecked after asynchronous CWD preparation before supervisor spawn and again immediately before command IPC dispatch; a short-lived process-group anchor/IPC reaper owns cancellation, timeout, descendant cleanup and host teardown without changing host signal behavior. Background group members cannot outlive the command. POSIX standalone Node.js with public SEA detection is required: Windows, Bun/compiled Pi, Node SEA applications and unknown interpreter capabilities are refused before approval or subprocess startup. Processes that deliberately escape the group are not sandboxed. See the core README for lifecycle qualifications; no post-dispatch rollback is promised.

## Not a security boundary

Approval is not an OS sandbox. Extensions and local event-bus callbacks are trusted same-process code. Command/mutation-shaped noncanonical calls (own `command`, or `path` plus content/edit properties, including one `input` envelope) and tools declaring these known schema properties even when optional are denied unless exactly one synchronous cooperative adapter advertises the current effective schema by object identity on `signalridge:approvals:adapter:v1`. See the core contract for validators and response shape. No source-name heuristic authorizes aliases; older command adapters without the capability are blocked. Unrelated metadata tools are not blanket-blocked.

The root public hook has no post-handler check. Known schema properties are conservatively classified before later normalizers run; arbitrary unknown properties, schema compositions/references and arbitrary extension semantics are **not** a sandbox. This bounded policy does **not** detect arbitrary evaluation/execution in tools without known command/mutation shapes; those tools, child runtimes, MCP tools, and external processes need separately restricted admission or explicit integrations. Cooperative peers are trusted to gate their final backend operation and to attest only while their own context/binding remains live. Captured services fail closed; absence is not permission to bypass a previously loaded service.

File reviews retain native edit BOM/CRLF/fuzzy/original-batch semantics. Limits: 256 KiB files/input, 64 KiB review, no clipped approval. Before synchronous diff generation, before/after together must have at most 2,048 line tokens counted by `split("\n").length` (including empty/trailing tokens); larger files fail without requesting approval or writing even for small edits. Invalid UTF-8/binary files and target symlink/hardlink aliases are rejected; display controls are explicitly escaped, actual byte hashes are complete. Stable ancestor symlinks are permitted with identity/realpath rechecks. Queue and post-review checks are not OS-atomic against external writers/aliases/processes. Approved write directory creation may remain after a subsequent failure/cancellation; no rollback is promised.

Full reviewed changes/commands can contain secrets. The broker shows them only in human reviews; its pending notices, status, errors, and lifecycle metadata do not echo proposed credentials. Native SDK tool output/error behavior is retained. Loading third-party extensions remains a trust decision.
